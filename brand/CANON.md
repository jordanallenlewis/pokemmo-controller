# Canon: one source for how everything looks and reads

Standing rule (Jordan, 2026-11-18). Everything about PokeMMO Controller (README, website, app, command-line output and help, docs, release notes, wheel labels, issue templates, drafts, listings) takes its fonts, type sizes, images and words from `brand/`. Nothing copies them.

| What | Source | Used by |
|---|---|---|
| Colours, fonts, radius, type sizes | `tokens.json` (`dark`, `light`, `type`, `scale`, `fonts`) | `build.py` writes `tokens.css` and the app page; the website uses the same values |
| Product, system and pad names, wrong spellings | `glossary.json` | `check.py` |
| Action and button names per pad | `tools/layout.py` (`ACTIONS`, `PADS`) | app, website data, README tables (generated by `site/build.py`) |
| Images | `images.json` (the allowed set) and the files it names | README, docs, website, app |
| Voice | `VOICE.md` | all copy |

## README (GitHub cannot load web fonts)

GitHub draws the README in its own font, so the canonical README style is these conventions plus canonical images:

- Name: **PokeMMO Controller**. Systems: Windows, macOS, Linux, Steam Deck. Pads: Xbox, PlayStation, Switch Pro, Steam Deck. Say **D-pad**, **wheel**, **stick**, **controller** (not gamepad, joystick, radial menu).
- Headings: one `#` title, `##` sections, `###` inside a section. No bold text standing in for a heading, no emoji.
- Buttons and keys: as printed on the pad the player holds; code, commands, file names and paths in backticks.
- Images: only from the set in `images.json` (the real controller photos and the art rendered from them), always with alt text, light and dark variants through `<picture>`.
- Tables and generated blocks come from `site/build.py`; never edit between the `generated` markers.

## Checking

`python brand/check.py` (also in the tests, so CI on every system runs it) fails on a non-canonical word, a font outside `fonts.allowed`, a size off `scale`, or an image outside the set. `known-drift.json` lists the sizes the website and the app still use off the scale; it can only shrink, and the test fails when an entry is fixed but still listed.

## Adapts to any screen

The second standing rule lives in `CONTRIBUTING.md` ("Everything adapts live to the screen"): sizes come from the player's setting and the game window, never fixed pixels, and the screen sizes it must hold at are the CI matrix.
