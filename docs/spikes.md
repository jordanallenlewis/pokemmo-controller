# Hardware spikes (M0)

These are the open questions from `docs/FOUNDATION.md` that only a real machine can answer. Nobody has run them yet: this page says what each one asks, how to run it, and what each answer changes. Until a person writes a result here, the answer is **unverified** and the website and README make no promise about it.

| # | Question | Status | Needs |
|---|---|---|---|
| 1 | Does Steam reload a rewritten wheel layout while PokeMMO runs? | unverified | Windows PC with Steam, PokeMMO, a pad |
| 2 | Do SDL3 pad names match the names PokeMMO logs, on Windows, macOS and Deck? | unverified | one machine per OS, pads |
| 3 | Which SDL build does PokeMMO ship? | unverified | any machine with the client (read-only look at the client files) |
| 4 | Can SDL run on the main thread under Tauri on macOS? | unverified | a Mac (Apple silicon) |
| 5 | Does a Tauri AppImage start on a Steam Deck in Desktop and Game Mode, also as a non-Steam game? | unverified | a Steam Deck |

Nothing here is checked by CI, and the sandbox this project is developed in has no Deck, Mac, Steam, PokeMMO or controller.

## 1. Steam wheel hot-reload
- **Run:** with PokeMMO started from Steam and the wheel visible, run `pmc wheel size` (or edit the layout by hand) so the `.vdf` changes. Open the wheel again. Did the new size show without restarting the game?
- **If it reloads:** the Wheel tab says the size applies at once.
- **If not:** the tab says "Size updates the next time PokeMMO starts from Steam" and `pmc follow --once` runs from the shortcut's launch options.

## 2. SDL3 pad names
- **Run:** plug in an Xbox, a PlayStation and a Switch Pro pad. Compare the name SDL3 reports (`pmc input --json`, once it exists, or `SDL_GetGamepadName` in a small test) with the controller names in PokeMMO's own log.
- **Changes:** the list of names the native map is filed under. Today the project files the map under every name it knows plus every pad PokeMMO logged on the machine.

## 3. PokeMMO's SDL build
- **Run:** list the SDL library files in the client folder and read their version strings (read-only; touch nothing in the game folder).
- **Changes:** whether the app's pad reading can disagree with the game's about button numbers.

## 4. SDL on the macOS main thread
- **Run:** build the spike with SDL pumped from the Tauri `run_on_main_thread` timer. Press every button; watch for missed events or a frozen window.
- **If it fails:** the documented fallback is a `pmc input --json` child process.

## 5. Tauri AppImage on a Deck
- **Run:** copy the AppImage to a Deck. Start it from Desktop Mode, then add it as a non-Steam game and start it in Game Mode. Note whether FUSE is needed, whether the pad drives the app, and whether it closes cleanly.
- **If FUSE AppImages fail as a non-Steam game:** the shortcut points at an extracted copy and `pmc-update` swaps a `current` link.

## Other gaps
- **v1.0.0 sandbox golden:** the `v1.0.0` tag has no `tools/setup.py`, so the update-from-v1.0.0 scenario cannot be generated by the same script as the later tags. The golden set covers v1.1.0 and v1.2.0. A v1.0.0 case needs its own generator, or a decision that it is out of scope.

## How to report a result
Open an issue or tell the maintainer: the machine and OS, the pad, what you did, what you saw. A result is written into this page with the date and who ran it. Until then every row above stays "unverified".
